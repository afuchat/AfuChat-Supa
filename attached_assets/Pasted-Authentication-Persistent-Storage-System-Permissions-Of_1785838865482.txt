Authentication, Persistent Storage, System Permissions & Offline Experience Fix

The app currently has a critical issue where all locally stored data is lost after the app is closed and reopened. This must be fixed.

Authentication & Startup

- Users must remain signed in until they explicitly log out.
- Never log users out because they are offline.
- Never clear authentication tokens, refresh tokens, or user data during app startup.
- Restore the saved session before rendering the application.
- Display a splash/loading screen while restoring local data and authentication.
- Only show the login screen if no valid session exists after restoration.
- If a valid session exists, the app must always open directly to the Chats screen.

Persistent Local Storage

Investigate why local storage is being reset after every app restart.

Verify that all locally stored data persists across app restarts, including:

- Authentication session
- Refresh tokens
- User profile
- User preferences
- Dismissed popup states
- Cached conversations
- Cached messages
- Cached contacts
- Cached media metadata
- App settings
- Any other offline application data

Search the project for any code that clears storage, including:

- AsyncStorage.clear()
- AsyncStorage.removeItem()
- SecureStore.deleteItemAsync()
- MMKV.clearAll()
- Any custom storage reset or cache-clearing functions executed during startup.

System Permissions & Cross-Device Stability

Introduce a proper system permissions and device authorization layer to ensure stable synchronization and consistent behavior across multiple devices.

- Implement a unified permission management system for all sensitive features (storage, notifications, media access, background sync).
- Ensure permissions are requested only when needed and are persistently stored without being reset on restart.
- Add device-level identification and authorization to support secure cross-device syncing of the same account.
- Ensure each device session is properly registered and validated with the backend to prevent conflicts or duplicate sessions.
- Maintain a consistent sync state across devices so that changes made on one device are reliably reflected on others.
- Prevent data corruption or overwrites by implementing conflict resolution rules during multi-device synchronization.
- Ensure background sync permissions are properly configured so the app can safely sync data even when running in the background or when reopened after being closed.

Offline Experience

The app should function as an offline-first application.

This must apply across the entire app: anything that is accessible when online must also remain accessible offline. All navigation must avoid using direct route paths like "/page". Instead, introduce a unified navigation protocol/abstraction layer that works identically in both offline and online states. Only features that explicitly require live internet data (such as fetching new messages, syncing, or real-time updates) should be unavailable when offline. Everything previously loaded or cached must remain fully usable.

When there is no internet connection:

- Users must still be able to open the app.
- Users must remain logged in.
- The app must still open directly to the Chats screen.
- Previously loaded chats must remain accessible.
- Previously downloaded messages must remain readable.
- Previously loaded contacts and profiles must remain available.
- Previously loaded images, files, and other cached content should remain accessible if already stored locally.
- Users should be able to browse any content that had already been synchronized before going offline.

When the internet connection returns:

- Automatically synchronize new messages and changes.
- Upload any pending actions performed while offline.
- Refresh cached data in the background without interrupting the user.
- Resolve synchronization safely without logging the user out.

Startup Flow

The startup sequence must be:

1. Launch application.
2. Show splash/loading screen.
3. Restore persistent local storage.
4. Restore authentication session.
5. Load locally cached user data.
6. If authenticated, navigate directly to the Chats screen.
7. Begin background synchronization if internet is available.

Testing Requirements

Verify that after force-closing and reopening the app:

- The user is still logged in.
- The app opens directly to the Chats screen.
- Dismissed popups remain dismissed.
- User preferences remain unchanged.
- Cached chats and messages remain available.
- The app works normally without an internet connection using previously synchronized data.
- No locally stored data is lost between app restarts.

The objective is to make the application behave like modern messaging apps, where users stay signed in indefinitely, the app opens directly into their conversations, and previously synchronized content remains available even when the device is offline.
